## Context

ohm is a personal knowledge system. As of today it is these repositories (GitHub owner `haeinej`, local root `~/development/november 2026/`):

| Repo | Local folder | Role |
| --- | --- | --- |
| `haeinej/ohmmmm` (was ohm-vault, earlier ohm-content-layer; old URLs redirect) | `ohmmmm/` | The person's home: `vault/` (content: blocks, channels, visibility layers, vault service), `cortex/` (agent memory, merged from archived ohm-cortex), `home/`, `contract/`, `bin/ohmmmm.mjs` |
| `haeinej/ohm-onboarding` | `ohm-onboarding/` | Account app: sign-in (AT OAuth), onboarding, grants, profile draft, private-vault keys (`packages/keys`, `com.ohmmmm.keys.*`) |
| `haeinej/ohm-ux` | `ohm-ux/` | Workspace UX wireframe (React 19, Vite, Tiptap, d3, base-ui/shadcn on the ohm design system). Runs only on sample data. **To be moved into ohmmmm as `app/`.** |
| `haeinej/ohm-site` | `ohm-site/` | ohmmmm.com (`home/`) and docs.ohmmmm.com (`docs/`, generated by `docs/build.py`, reads sibling `../ohmmmm/vault`) |

## Rules that bind every WP

1. **Never rename these runtime names** (they keep `ohm-vault` on purpose): the Cloudflare Worker and D1 database `ohm-vault`; the `VAULT -> ohm-vault` service binding; the MCP server `ohm-vault` and its `vault_*` tools; key/crypto context strings `ohm-vault/file/v1`, `ohm-vault/master/v1`, `ohm-vault unlock v1`, `ohm-vault/unlock-user/v1`, `ohm-vault/link/v1`; IndexedDB name `ohm-vault`; export file `ohm-vault.json`; `ohm-onboarding/vendor/ohm-vault` and its pin. Plans, migrations and dated history stay as written.
2. **Deliberate non-exposure, keep it:** `addFriend` is session-only (an agent must never widen who can read); `com.ohmmmm.keys.*` is session-only; the server never gets private plaintext, so no server-side agent tool may return private content. Account requests ride on the ohm session.
3. No deploys, no `wrangler d1 execute` against remote, no migration applied anywhere real, no merging your own PRs. Local secrets (`vault/cirrus/.dev.vars`, `vault/service/wrangler.deploy.jsonc`) are gitignored; never print or commit them.
4. Use only words from `ohmmmm/docs/words.md`. If two parts disagree, settle it there in the same PR.
5. Node: use 22.19 or newer (ohm-onboarding's undici needs it; CI uses Node 22/24). Run `npm test` at the ohmmmm root before every PR; ohm-onboarding: `npm run check && npm run boundaries:check`.
6. Synthetic people and data only in tests and docs. Document each chunk for people and for agents (vault's document-work skill).

**Hard constraints that shape the app (from code, not opinion):**
- The vault service sends no CORS headers; a browser reaches it only same-origin at `https://app.ohmmmm.com/vault` (cookie session; non-GET needs `Origin == OHM_APP_ORIGIN`; optional `X-Ohm-Did` precondition). See `vault/service/src/worker.mjs`, `ohm.mjs`.
- A hosted page **cannot** reach the cortex or the local vault index: `cortex serve` (`cortex/src/http.mjs`) is MCP-over-HTTP at `/mcp`, loopback-only origins, bearer token from `cortex token`, no CORS/OPTIONS; the vault index/journal (`.vault/index.sqlite`, `.vault/journal.jsonl`) has no server at all (`ohm vault …` CLI only).
- Private blocks are encrypted/decrypted only on the device with `ohm-onboarding/packages/keys` (`sealFile`, `openFile`, `vaultPrivateFiles`, `sessionKeyStore`).

### WP5 — Agent connectivity in the app, without UI SDK (app; after WP1, alongside WP6)
UI SDK is dropped (decision 3). The app keeps base-ui (through ohm-ui) and its own helper, `app/src/webmcp.ts`, under the rules in `app/AGENTS.md`. Borrow these of UI SDK's ideas, built on what the app already has:
- **A confirm sentence on lasting actions.** Every control whose action lasts says what it does in one sentence (as UI SDK's `data-agent-confirm` did), and its tool shows the `ApprovalCard` before running (app rules 11–12). This covers visibility raises (private→friends discloses; →public publishes), delete, publish, friend removal, and master-key and device actions.
- **Who made a change.** Every change the store applies carries `source: 'person' | 'agent'`, so the bell and `AgentStatus` show what an agent changed, and "undo what the agent did" can find it.
- **A snapshot of the screen.** A read-only tool, `workspace.snapshot`, lists the tools on screen now with their labels and state, so an agent can find its way without reading pixels.
- **Layering.** A tool exists only while its step is on screen (app rule 4). Domain actions are tools: the editor's setTitle, appendMarkdown and insertLink; the tree's move and reorder; the graph's centre, focus and filter. An agent never types into the editor's contentEditable or drags the SVG.
- **WebMCP needs Chrome 149+** (an origin trial, or `chrome://flags/#enable-webmcp-testing`), plus an Edge trial; Firefox and Safari have not committed. Elsewhere the page registers nothing, so the stdio MCP from WP4 and `ohmmmm serve` stay the portable paths.
- Done when: every interactive step has its tool; an agent can complete the workspace flows through tools alone; every lasting change either asks the person or is refused; Playwright checks keyboard, focus, ARIA and the tool paths.
