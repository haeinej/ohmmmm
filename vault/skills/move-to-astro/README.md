# Keep your website when it starts reading from ohm

You can use the same website after moving its published content into ohm.
Your coding agent makes an Astro copy that reads the channels you agreed on.
Readers should see the same pages, styles, links and addresses.

Before the trial, agree which public content belongs in each channel. This
lets the agent connect an Astro collection to the right records. With the
initial PDS loader, the matching posts must already be available as ohm
standard.site documents for a PDS-backed preview. While those records are being
prepared, the agent can use your existing public site content through the
loader's source interface to build and compare the Astro copy. The site guides
explain which source the preview reads and what remains for remote integration.
Only you decide what to publish.

Ask the curator to use [move-to-astro](SKILL.md). It takes a baseline from your
site, including desktop and phone screenshots. If your site is already built
in Astro, the agent adds the loader behind its existing pages. Otherwise, it
builds the same layouts in Astro on a copy and adds the loader there. Astro
assembles the pages and the loader supplies the published content.

The comparison also checks how the preview serves addresses, redirects,
directory listings and video requests. These settings matter even when the
generated pages contain exactly the same HTML.

Review the preview and the comparison report. Look at the pages, addresses,
links and media you care about, and check any differences the agent lists.
You can leave the copy as a preview, ask for a change, or approve replacing
the live site. Until that approval, visitors keep using the existing site.

The [baseline and content map](../migrate-site/SKILL.md) and the
[loader guide](https://github.com/haeinej/ohmmmm/tree/main/vault/astro) explain
what the agent needs to complete the copy.
